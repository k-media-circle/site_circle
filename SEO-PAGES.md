# Автоматическая публикация с сохранением SEO

GitHub Pages публикуется через .github/workflows/seo-pages.yml после каждого push
в main. Сборка запускает python build-seo-pages.py --stage, восстанавливает
согласованные метаданные главной, HTTPS, canonical, JSON-LD и robots.txt,
пересобирает страницы сообщества/проектов и sitemap.xml, публикует папку _site.

Исходные index.html и content.json редактора должны содержать одинаковые данные.
При временном расхождении двух файлов сборка завершится ошибкой; предыдущий сайт
останется доступен. Завершите экспорт обоих файлов и проверьте следующий запуск
в Actions. Сборка не записывает изменения обратно в репозиторий.

Нельзя удалять build-seo-pages.py, .github/workflows/seo-pages.yml, media/,
CNAME и проверочные HTML-файлы Google/Яндекса. Доменные настройки и HTTPS сохранены.
Технические инструкции и Python-файл не включаются в публикуемый каталог.

Для проверки локально: python build-seo-pages.py --stage. Для ручной повторной
публикации: Actions → Build and publish website → Run workflow.

Новые записи типа project с demo=false и безопасным slug автоматически получают
страницу. Подробные тексты берутся из blocks. Для уже существующих четырёх проектов
короткие аннотации заданы в генераторе, для новых используются содержательные
текстовые блоки. Инструменты без содержательной документации не публикуются отдельно.

Внешний редактор должен обновлять существующий репозиторий, сохраняя файлы сборки.
Полная замена/удаление репозитория этим процессом не защищается.
